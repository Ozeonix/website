# Ozeonix Infinity — Brand & UI/UX Precedence Rules

## 1. Precedence Hierarchy

When implementing or modifying UI, user flows, or styles in this repository, AI agents and developers must strictly adhere to the following order of authority:

1. **Explicit User Requirements**: Instructions provided directly by the user for the current task, provided they do not violate core security, repository constraints, or safety guardrails.
2. **Permanent Brand Rules & Canonical Design System**:
   - [AGENTS.md](../../AGENTS.md) (top-level project constitution).
   - [docs/design-system.md](../../docs/design-system.md) and [src/styles.css](../../src/styles.css) (the single source of truth for color tokens, typography scales, spacing, and component states).
3. **Integration Precedence Rules**:
   - This document ([.agents/rules/brand-precedence.md](brand-precedence.md)), defining the relationship between Ozeonix brand standards and external design intelligence.
4. **Local Brand Skill**:
   - [.agents/skills/brand-design-system/SKILL.md](../skills/brand-design-system/SKILL.md), enforcing Ozeonix Infinity's specific color tokens and styling conventions.
5. **External Design Intelligence Suite**:
   - Vendored skills from UI/UX Pro Max suite ([.agents/skills/ui-ux-pro-max/](../skills/ui-ux-pro-max/), `banner-design/`, `brand/`, `design/`, `design-system/`, `slides/`, `ui-styling/`), providing general UX, accessibility, banner layouts, and interaction patterns.
   - **Crucial Rule**: External scripts (e.g., in `brand/`, `design-system/`, or `ui-styling/`) must never overwrite Ozeonix tokens in `src/styles.css` or `docs/design-system.md`, nor generate conflicting `tailwind.config.js` or `tokens.json` files.

_If any ambiguity or conflict arises, higher-level rules strictly override lower-level suggestions. Never invent new brand palettes, random gradients, or unsupported component libraries._

## 2. Mandatory Brand Color Palette & Precedence Rules

This project strictly enforces an **Orange & Neutral Theme with Subtle Cyan/Blue Geometric Accents**:

| Role                     | Tailwind Class             | Hex Code              | Usage                                                     |
| :----------------------- | :------------------------- | :-------------------- | :-------------------------------------------------------- |
| **Primary Brand**        | `orange-600`               | `#ea580c`             | Primary CTA buttons, key headings, active link highlights |
| **Primary Hover**        | `orange-700`               | `#c2410c`             | Hover state for buttons and links                         |
| **Brand Accent / Bar**   | `orange-500`               | `#f97316`             | Announcement tickers, badge accents, logo border          |
| **Brand Deep**           | `orange-800`               | `#9a3412`             | Prominent logo text, bold title                           |
| **Brand Surface / Tint** | `orange-50` / `orange-100` | `#fff7ed` / `#ffedd5` | Active tab backgrounds, soft hover highlight states       |
| **Secondary Accent**     | `blue-300` / `blue-600`    | `#93c5fd` / `#2563eb` | Background decorative SVGs, secondary badges              |
| **Glow / Shadow Accent** | `indigo-600`               | `#4f46e5`             | Subtle glow shadows (`rgba(79, 70, 229, 0.4)`)            |
| **Light Background**     | `gray-50` / `white`        | `#f9fafb` / `#ffffff` | Page body background and card surfaces                    |
| **Dark Background**      | `gray-800` / `gray-900`    | `#1f2937` / `#111827` | Dark mode body and card surfaces                          |
| **Light Text**           | `gray-900` / `gray-700`    | `#111827` / `#374151` | High contrast headings and body text                      |
| **Dark Text**            | `gray-100` / `gray-300`    | `#f3f4f6` / `#d1d5db` | Dark mode text elements                                   |
| **Borders**              | `gray-200` / `gray-700`    | `#e5e7eb` / `#374151` | Subtle divider lines and card borders                     |

### Color Rules:

- All UI colors must resolve to centralized tokens in `src/styles.css`.
- Primary actions and CTAs must use `orange-600` (`#ea580c`, `var(--brand-orange)`), hovering to `orange-700` (`#c2410c`, `var(--brand-orange-hover)`).
- Secondary actions, announcement bars, and badge accents use `orange-500` (`#f97316`, `var(--brand-accent)`) or secondary blue accents (`#93c5fd` / `#2563eb`).
- Card and surface elevation shadows use subtle glow accents (`rgba(79, 70, 229, 0.4)` / `#4f46e5`).
- **Strict Prohibition**: Never adopt an external color palette, arbitrary hex, pastel spa theme, or multi-color gradient generated by an external skill. Local tokens take absolute precedence.

## 3. Permitted Uses of UI/UX Pro Max

The vendored UI/UX Pro Max skill ([.agents/skills/ui-ux-pro-max/](../skills/ui-ux-pro-max/)) may be consulted for:

1. **Information Architecture & Page Layout**: Section rhythm, content hierarchy, and conversion-focused structures.
2. **UX Flow & Interaction Design**: Empty states, loading states, error presentation, and micro-interactions.
3. **Responsive Behavior**: Mobile-first layout adaptations, breakpoint discipline, and touch usability.
4. **Accessibility (WCAG 2.2)**: Keyboard navigation tab orders, visible focus states (`var(--focus-ring)`), ARIA patterns, and screen reader announcements.
5. **Touch & Tap Ergonomics**: Minimum 44×44px hit targets and 8px+ spacing between interactive elements.
6. **Spacing & Visual Hierarchy**: White space proportion and content density dials.
7. **Stack-Specific Patterns**: Best practices for React, Radix UI, Lucide icons, and Tailwind v4.

## 4. Implementation Guardrails

- **Preserve Framework Architecture**: Respect TanStack Start full-stack SSR boundaries, file-based routing (`src/routes/`), loaders, actions, and `createServerFn` server functions.
- **Component Conventions**: Reuse existing Radix UI primitives, Lucide icons, `.oz-card` kinetic card styles, and `Reveal` transitions.
- **Forms & Validation**: Standardize all lead capture around `ProjectBriefForm` and its unified Zod schema.
- **Dependency Discipline**: Do not install new CSS packages, UI frameworks, or runtime libraries without explicit authorization.
- **Targeted Inspection**: Always read project documentation and inspect specific files before running broad searches.
- **Persistence Boundary**: Never allow `--persist` or `--design-system` flags from external scripts to overwrite local tokens or `docs/design-system.md`.

## 5. Verified Skill Invocation Pattern

_Sourced directly from vendored [.agents/skills/ui-ux-pro-max/SKILL.md](../skills/ui-ux-pro-max/SKILL.md) and `scripts/search.py`:_

The skill runs locally with zero external dependencies using Python 3:

```bash
# Query specific UX or accessibility guidelines:
python3 .agents/skills/ui-ux-pro-max/scripts/search.py "<query>" --domain ux

# Query layout or responsive guidelines:
python3 .agents/skills/ui-ux-pro-max/scripts/search.py "<query>" --domain style

# Query stack-specific patterns (e.g. React / Tailwind):
python3 .agents/skills/ui-ux-pro-max/scripts/search.py "<query>" --stack react

# Query structured product patterns:
python3 .agents/skills/ui-ux-pro-max/scripts/search.py "<product_type> <keywords>" --design-system -p "Ozeonix Infinity"
```

> **Advisory Nature**: The skill provides design recommendations and pattern intelligence. It does **not** independently authorize code changes, create Git commits, or override Ozeonix Infinity's permanent brand tokens.
